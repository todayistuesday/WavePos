# MOBILE_SETTLEMENT

## 목적
- POS 하단 모드 토글의 `모바일 정산`으로 진입하는 모바일 전용 키밴드 후불 정산 화면 요구사항을 정의한다.
- 현장 운영자가 실제 고객 휴대폰 화면처럼 검토할 수 있도록 별도 모바일 화면 기준을 문서화한다.

## 진입 방식
- 기존 POS 푸터의 모드 토글에서 `모바일 정산`을 선택하면 앱 전체가 모바일 정산 화면으로 전환된다.
- 모바일 정산 화면은 POS 위 팝업이 아니라 독립 화면처럼 동작해야 한다.
- 모바일 정산 화면은 독립 URL 상태로 직접 진입할 수 있어야 한다.
- 기존 `일반 포스`, `키밴드 정산` 화면의 레이아웃과 기능은 유지한다.

## 기기 프리셋
- 화면 프리셋은 `iOS`, `Android`, `태블릿` 3가지를 제공한다.
- `iOS` 기준 크기는 `390 x 844`를 사용한다.
- `Android` 기준 크기는 `360 x 800`을 사용한다.
- `태블릿` 기준 크기는 `768 x 1024`를 사용한다.
- 작은 뷰포트에서는 동일 비율의 모바일 전용 레이아웃으로 축소 표시한다.
- 기기 프리셋 선택 토글은 화면 상단 바깥 영역에 두고, 본문 내부에 중복 가이드 문구를 반복 표시하지 않는다.

## 헤더 / 푸터
- 헤더는 중앙 정렬 기준으로 타이틀 `키밴드 후불 정산`만 표시한다.
- 브랜드명 `메이크티켓` 텍스트는 모바일 정산 헤더에 노출하지 않는다.
- 푸터는 `Copyright © smartix Corporation. All right reserved` 문구만 표시한다.

## 조회 영역
- 키밴드 조회 입력 필드와 `조회`, `초기화` 버튼을 제공한다.
- 조회 입력 placeholder는 `키밴드 번호를 입력하세요.`를 사용한다.
- 조회 기준은 키밴드 번호, 예약번호, 전체 휴대폰 번호를 사용한다.
- 모바일 정산에서는 키밴드 발급 기능을 제공하지 않는다.
- 기기 프리셋 토글이 별도로 있으므로 조회 영역 내부에는 `iOS 390 x 844`, `태블릿 768 x 1024` 같은 추가 가이드 문구를 표시하지 않는다.
- 조회 버튼은 POS 주요 액션과 동일한 보라색 톤을 사용한다.

## 조회 내역 리스트

### 기본 동작
- 키밴드 조회 결과만 리스트에 누적 표시한다.
- 장바구니, 선택 내역, POS 우측 결제 패널은 사용하지 않는다.
- 각 조회 카드는 키밴드 단위로 구분한다.
- 각 조회 카드 상단에는 어떤 키밴드 조회 결과인지 알 수 있도록 키밴드 번호를 표시한다.
- 각 키밴드 조회 카드는 개별 삭제할 수 있는 `X` 버튼을 제공한다.

### 표시 항목
- 조회 내역에는 현장 구매 이력 기준으로 `상품명`, `권종명`, `수량`, `금액`만 표시한다.
- 항목 헤더는 `상품명 / 권종명 / 수량 / 금액` 4개 컬럼으로 구성한다.

### 제외 항목
- 예약번호는 모바일 조회 내역에서 표시하지 않는다.
- 고객명은 모바일 조회 내역에서 표시하지 않는다.
- 휴대폰 번호는 모바일 조회 내역에서 표시하지 않는다.
- 회차 정보(`00:00 ~ 00:00`)는 모바일 조회 내역에서 제외한다.
- 기간 정보(`yyyy-mm-dd ~ yyyy-mm-dd`)는 모바일 조회 내역에서 제외한다.
- 예매 정보, 예약 식별 정보, 고객 식별 정보는 카드 상단의 키밴드 번호 외에는 노출하지 않는다.

### 시각 규칙
- 리스트 헤더 하단선과 첫 행 상단선이 중복되어 두 줄처럼 보이지 않도록 정리한다.
- 조회 카드 안의 정보 구분선은 필요한 최소 수준만 유지한다.

## 결제 영역
- 조회 결과 전체를 기준으로 결제 금액을 계산한다.
- 결제 버튼은 POS 주요 액션과 동일한 보라색 톤을 사용한다.
- 결제 버튼 라벨은 `결제 하기`를 사용한다.
- `온라인 PG 결제하기` 같은 긴 문구는 사용하지 않는다.
- 결제 버튼 하단의 별도 안내 문구는 노출하지 않는다.

## 부가 기능
- 모바일 정산 화면에서도 현재 화면을 PNG로 복사하는 `스크린샷` 기능을 제공한다.
- 스크린샷 버튼은 기기 프리셋 토글과 같은 상단 제어 영역에 배치한다.
